## Architecture Overview

```
+---------------------------+     Port 3000 (mTLS/OIDC)    +---------------------------+
|   Kubernetes Cluster    | ----------------------------> |      Edge Node            |
|                         |                                |                           |
|  +------------------+   |                                |  +--------------------+   |
|  | Virtual Kubelet  |   |                                |  | interLink API      |   |
|  | (Helm deployed)  |   |                                |  | (port 3000)        |   |
|  +--------+---------+   |                                |  +---------+----------+   |
|           |             |                                |            |              |
|           |             |                                |            | localhost    |
|           |             |                                |            v              |
|           |             |                                |  +--------------------+   |
|           |             |                                |  | Plugin             |   |
|           |             |                                |  | (port 4000)        |   |
|           |             |                                |  +--------------------+   |
+---------------------------+                                +---------------------------+
```

**Network Requirements:**
- Edge node must be reachable from Kubernetes cluster on port 3000 (or custom)
- Plugin communicates with interLink API over localhost (port 4000)
- Firewall should restrict access to Kubernetes cluster CIDR only

---

## Authentication Options

InterLink supports two authentication methods:

| Method | Best For | Complexity | External Dependencies |
|--------|----------|------------|----------------------|
| **[mTLS](#mtls-authentication)** | Private networks, HPC, testing | Low | None |
| **[OIDC/OAuth2](#oidc-authentication)** | Multi-tenant, enterprise SSO | Medium | Identity Provider |

:::tip Recommendation

For most deployments, **mTLS is recommended** - it's simpler to set up and doesn't require an external identity provider. See the [Quickstart](../quickstart) for mTLS setup.

:::

## Installation

### Prerequisites

**Edge Node:**
- Linux (Ubuntu 20.04+, RHEL 8+, or similar)
- Docker Engine **or** SLURM with Singularity
- `wget`, `jq`, `curl`, `openssl` installed
- Outbound internet access (for downloading binaries)

**Kubernetes Cluster:**
- Helm 3.x installed
- `kubectl` configured
- Network access to edge node on port 3000

### Step 1: Download interLink

```bash
mkdir -p $HOME/.interlink/{bin,config,certs,logs}
export VERSION=$(curl -s https://api.github.com/repos/interlink-hq/interlink/releases/latest | jq -r .name)
wget -O $HOME/.interlink/bin/interlink \
  https://github.com/interlink-hq/interLink/releases/download/$VERSION/interlink_Linux_x86_64
chmod +x $HOME/.interlink/bin/interlink
```

### Step 3: Configure and Start Plugin

<Tabs groupId="plugin-type">
  <TabItem value="docker" label="Docker Plugin" default>

**Requirements:** Docker Engine installed, user in `docker` group

```bash
# Create configuration
cat > $HOME/.interlink/config/plugin-config.yaml << EOF
Socket: "unix://$HOME/.interlink/.plugin.sock"
InterlinkPort: "0"
SidecarPort: "4000"
DataRootFolder: "$HOME/.interlink/jobs/"
BashPath: /bin/bash
VerboseLogging: false
EOF

# Download plugin
export PLUGIN_VERSION=$(curl -s https://api.github.com/repos/interlink-hq/interlink-docker-plugin/releases/latest | jq -r .name)
wget -O $HOME/.interlink/bin/plugin \
  https://github.com/interlink-hq/interlink-docker-plugin/releases/download/${PLUGIN_VERSION}/docker-plugin_Linux_x86_64
chmod +x $HOME/.interlink/bin/plugin

# Start plugin
export INTERLINKCONFIGPATH=$HOME/.interlink/config/plugin-config.yaml
$HOME/.interlink/bin/plugin &> $HOME/.interlink/logs/plugin.log &
echo $! > $HOME/.interlink/plugin.pid

# Verify
sleep 2 && tail -n 10 $HOME/.interlink/logs/plugin.log
```

  </TabItem>

## Kubernetes Deployment

### Create Certificate Secret (mTLS only)

```bash
# Create namespace
kubectl create namespace interlink

# Create secret with client certificates
# Secret name must match pattern: <nodeName>-tls-certs
kubectl create secret generic my-node-tls-certs \
  --from-file=ca.crt=/path/to/ca.pem \
  --from-file=tls.crt=/path/to/client-cert.pem \
  --from-file=tls.key=/path/to/client-key.pem \
  -n interlink
```

### Deploy with Helm

```bash
# Create values file
cat > interlink-values.yaml << 'EOF'
nodeName: "my-node"

virtualNode:
  resources:
    CPUs: 8
    memGiB: 49
    pods: 100

interlink:
  enabled: false
  address: https://YOUR_EDGE_NODE_IP
  port: 3000
  tls:
    enabled: true
EOF

# Replace with your edge node IP
sed -i "s/YOUR_EDGE_NODE_IP/YOUR_ACTUAL_IP/g" interlink-values.yaml

# Deploy
export INTERLINK_CHART_VERSION=$(curl -s https://api.github.com/repos/interlink-hq/interlink-helm-chart/releases/latest | jq -r .tag_name | sed 's/interlink-//')
helm upgrade --install \
  --create-namespace \
  -n interlink \
  my-node \
  oci://ghcr.io/interlink-hq/interlink-helm-chart/interlink \
  --version $INTERLINK_CHART_VERSION \
  --values interlink-values.yaml
```

:::warning Chart Version

Always use the [latest chart version](https://github.com/interlink-hq/interlink-helm-chart/blob/main/interlink/Chart.yaml) compatible with your interLink version.

:::

## Verification

### Check Node Status

```bash
# Watch for node to become ready
kubectl get nodes -w

# Expected output:
# NAME       STATUS   ROLES    AGE   VERSION
# my-node    Ready    <none>   60s   v1.27.0
```

### Deploy Test Pod

```bash
kubectl apply -f - <<EOF
apiVersion: v1
kind: Pod
metadata:
  name: test-edge
spec:
  nodeSelector:
    kubernetes.io/hostname: my-node
  tolerations:
    - key: virtual-node.interlink/no-schedule
      operator: Exists
  containers:
  - name: test
    image: busybox:latest
    command: ["sleep", "3600"]
EOF

# Check status
kubectl get pod test-edge -o wide
```

### Security Hardening

1. **Firewall Configuration:**
   ```bash
   sudo ufw allow from <K8s-cluster-CIDR> to any port 3000
   sudo ufw deny 3000 comment "Block public access"
   ```

2. **Certificate Security:**
   - Private keys: `chmod 600`
   - Rotate certificates before expiration
   - Store CA key securely (offline/HSM)

3. **Monitoring:**
   - Enable verbose logging initially
   - Set up log rotation
   - Monitor failed authentication attempts

:::note

See the [Security Hardening Guide](#) (coming soon) for comprehensive security recommendations.

## Troubleshooting

### Node Not Ready

```bash
# Check Virtual Kubelet logs
kubectl logs -n interlink -l app=virtual-kubelet

# Common issues:
# - Network connectivity (test with: curl https://EDGE_IP:3000/pinglink)
# - Certificate mismatch (verify SANs match edge node IP)
# - Wrong IP in Helm values
```

### Plugin Not Responding

```bash
# Check plugin logs
tail -f $HOME/.interlink/logs/plugin.log

# Restart plugin
kill $(cat $HOME/.interlink/plugin.pid)
$HOME/.interlink/bin/plugin &> $HOME/.interlink/logs/plugin.log &
echo $! > $HOME/.interlink/plugin.pid
```

### Connection Refused

```bash
# Check if interLink is running
ps aux | grep interlink
netstat -tlnp | grep 3000

# Check firewall
sudo ufw status | grep 3000
```
